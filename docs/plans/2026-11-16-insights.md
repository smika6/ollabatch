# Insights, history, summaries and remote controls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Job history with details and optional AI summaries, inference and machine insights over time, and dashboard controls for machines whose owner allows it.

**Architecture:** The host parses Ollama's per-answer stats as results pass through, feeding a new `Insights` store (per-minute and hourly buckets) and per-job stats. History, summaries, settings and commands are host modules wired into `host.mjs` routes; agents pull desired settings and commands on their tick. The dashboard gains History, Insights and per-machine control panels built from pure, tested view helpers.

**Tech Stack:** Node >= 20, `node:test`, no dependencies; inline-SVG charts.

**Spec:** `docs/insights-design.md`

## Global Constraints

- Zero dependencies; agents outbound-only; loopback/Host/Origin rules unchanged; unknown values render "unknown", never 0; phone-usable; `.ps1` files ASCII-only.
- Retention: finished jobs and logs kept 90 days or the last 2,000 jobs (whichever is smaller); logs trimmed to their last 20 MB; pruned daily.
- Metrics: 24 h at 1-minute resolution, 30 days at 1-hour resolution.
- A model load = `load_duration` > 50 ms. Thrash warning: a card with > 6 loads in the last hour.
- Summaries: `summaries: 'off' | 'manual' | 'auto'` (default `manual`); lease timeout 2 min; unleased give-up 1 h; only trusted cards (the host's machine, or machines reporting `remote: true`); idle cards only (nothing else servable queued for them); secrets stripped; temperature 0.2; 3–6 sentences.
- Remote: `remote` default true only for `--trusted` installs (saved as `trusted: true`); per-field timestamps, newest wins; fullscreen/schedule pauses never remotely liftable; commands expire after 10 min; fixed slots 1–8.

## Review Focus

1. A streamed (NDJSON) answer, an embed answer, or a non-JSON body: stats parse from the last `done` line, partial stats, or nothing, never a crash (Task 1 `parses every answer shape`).
2. A remote settings edit arriving while the owner changed a different field on the PC: neither undoes the other (Task 5 `per-field newest wins`).
3. A summary while every card is busy with real work: it waits, never displaces a job's request or forces a model swap (Task 3 `summary waits for an idle trusted card`).
4. History growing for months: pruning keeps the newest 2,000 / 90 days and trims logs without touching running jobs (Task 2 `retention`).
5. An agent with `remote` off receiving commands: all rejected and reported as such; nothing applied (Task 5 `remote off rejects everything`).

### Task 3: AI summaries

**Files:** Create `src/summary.mjs`; modify `src/host.mjs`, `src/queue.mjs` (per-request `leaseMs`); test `test/summary.test.mjs`.

**Interfaces:**
- `scrub(text): string` (drops lines matching `/(key|token|password|secret)\s*[=:]|bearer\s+\S+/i` and replaces runs of ≥32 base64/hex chars with `[redacted]`).
- `buildPrompt(job, logTail): { system, user }`.
- `summarize(job, { enqueue, pickModel, logTail }): Promise<{ text, model } | null>` — enqueues `{ jobId: '_summary', path: '/api/chat', body, leaseMs: 120000, signal (1 h) }`.
- Host settings `{ summaries, summaryModel }` in state; `GET/PUT /ob/settings`; `POST /ob/jobs/:id/summarize`; auto on finish when `summaries === 'auto'` or template `summary: true`; progress POST accepts `{ summary }` (source `job`).
- canServe for `'_summary'`: card trusted (machine === host's own hostname, or its report `remote: true`) AND no pending non-summary request it could serve AND (its reported loaded model is null or equals the summary model).
- [ ] Tests: `scrub` removes secrets; `summary waits for an idle trusted card` (busy trusted card + untrusted idle card → stays pending; once the trusted card is idle → served); job-supplied summary wins; `summaries off` → 409 on summarize.

### Task 5: Remote settings and commands — agent

**Files:** Modify `src/agent/config.mjs`, `src/agent/agent.mjs`, `src/agent/page/*`, `bin/ollabatch.mjs`; test `test/agent-remote.test.mjs`.

**Interfaces:**
- Config gains `trusted`, `remote`, `at: { [fieldPath]: number }` (set by local `act()` too); `cards[id].slots: 'auto' | n`.
- Each tick: `GET /pool/settings`; for each field with `at` newer than local `at[path]` and `remote` on → apply via `act()` with `source: 'remote'`; report `remote`, `appliedVersion`, `localOverride: [paths where local is newer]`, per card `loadedModel` (from the server's `/api/ps`).

- Fixed slots: `slots: n` pins the server's parallel count and skips the tuner.
- Local page: "Let the pool manage this PC" toggle; per card Slots (auto/1–8), Re-tune, Restart; "Pull a model".
- [ ] Tests: `per-field newest wins` (remote policy change + newer local downloads change → both kept; older remote field ignored and listed in `localOverride`); `remote off rejects everything`; fixed slots pin the server; restart-card command restarts; install `--trusted` saves `trusted` + `remote`.
