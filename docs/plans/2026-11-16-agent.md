# ollabatch step 2 (machine agent) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ollabatch agent`: one program per machine that finds its GPUs, runs and tunes a pinned Ollama per card, lends them to a host found on the network, steps aside for fullscreen programs, manages a size-limited model playground, and offers a local control page; plus the host and dashboard support for it.

**Architecture:** New modules under `src/agent/`, each pure or with injected I/O (command runner, fetch, clock) so they test without GPUs. `src/agent/agent.mjs` wires them. The step-1 join loop is refactored into a controllable card worker that the agent runs once per card. Host gains `/pool/release`, `/pool/machine`, `/pool/wants`, a UDP beacon, and agent-aware local-card startup.

**Tech Stack:** Node >= 20 ESM, `node:test`, `node:dgram`, `node:child_process`, `node:fs` (hard links). Windows probes run one long-lived PowerShell child (no native modules).

**Spec:** `docs/agent-design.md`

## Global Constraints

- Zero dependencies; Node >= 20; `npm test` = `node --test`; fixtures and helpers in `testdata/`.
- Agent dir default `~/.ollabatch/agent/` (`config.json`, `tuning.json`, `playground/`, `logs/`).
- Agent card servers listen on `127.0.0.1:11440 + n`; never touch the user's Ollama or ports it uses.
- Local page `127.0.0.1:11510`, loopback-only with the host's Host/Origin checks.
- Beacon: UDP 11501, every 5 s, payload `{"ollabatch":1,"name":<host machine>,"url":"http://<ip>:<port>"}`; never carries the password.
- Slot tuning: start 1; step up while last step gained >= 10% items/s, free VRAM >= max(1024 MB, 10% of total), no OOM; cap 8; measure window >= 20 completed requests or 3 min; step down on rate < 50% of tuned for 3 min with queued work, free VRAM under margin, or OOM; retry up no sooner than 15 min after a step down; saved tuning re-measured after 7 days or a different Ollama version.
- Lending policy values: `when-free` (default), `always`, `schedule`, `never`. `when-free` = pause a card while a program has been fullscreen on it for 10 s; resume 3 min after it leaves fullscreen or exits. Windows only; elsewhere acts as `always` and says so.
- Owner pause: abort in-flight requests, `POST /pool/release` them (no attempt counted), unload the model; target VRAM freed within 15 s.
- Playground default limit 50 GB; linked models count 0; locked and in-use models never evicted; one pull per machine at a time; downloads default on only with `--trusted`.
- `/pool/wants?machine=`: per card, models it would be used for: running `one` job → its chosen model; running `any` job → its list; queued job → its first model; only for cards whose effective labels match the job's selector.
- Host `--local` card is skipped when `GET http://127.0.0.1:11510/status` answers at startup; `--local` given explicitly forces it.
- Integrated GPUs under 4096 MB dedicated memory are reported but not lent by default.
- From `docs/prior-art.md`: values a driver doesn't report are `null` end to end and render as "unknown", never 0; the owner's rules are checked when the host asks and again right before a download or eviction; no code from AGPL projects (ideas only).

## Review Focus

1. The user's own Ollama is running on 11434 on the same GPU: the agent never stops or reconfigures it, skips any occupied port in 11440+, and that Ollama's GPU use is not a "fullscreen program" (Task 4 test `skips occupied ports`; Task 6 test `background GPU use never pauses`).
2. The host restarts or is unreachable while an agent runs: owner pause is still enforced locally, the agent re-registers with the same stable card ids (no duplicate cards on the dashboard) (Task 2 test `stable id across re-register`; Task 10 test `host down keeps local pause`).
3. A pull fails or the disk fills mid-download: no partial model is treated as present, nothing locked is evicted, the card keeps serving what it has (Task 7 test `failed pull leaves cache consistent`).
4. A driver reset or crash kills a card's Ollama mid-run: the server restarts with backoff, its in-flight requests are released, the tuner does not count the crash as a slowdown (Task 4 test `crash restarts with backoff`; Task 5 test `restart is not a slowdown`).
5. A fullscreen program on a monitor driven by card A renders on card B: card B pauses, card A keeps lending (Task 6 test `pauses the card the program uses`).
